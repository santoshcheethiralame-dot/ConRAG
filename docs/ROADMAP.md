# Roadmap

What was built from the improvement review is described in [ARCHITECTURE.md](ARCHITECTURE.md) and [DESIGN.md](DESIGN.md) (attribute-key candidates, graph expansion, per-source duplicates, stricter `supports`, judge hardening, CI eval gate). What is left, in suggested order:

| # | Item | Why | Notes |
|---|---|---|---|
| 1 | **Evaluation honesty** | The corpus and labels are written by the judge's author, and all 16 conflict questions have the better-supported side first, defined as the more trusted or newer source. "Leans right 16/16" mostly shows the formula equals the labelling rule. | Add questions where the newer or official source is wrong and where *undecided* is right; paraphrased questions; a held-out set the judge was not tuned on; confidence intervals (17/17 recall has a 95 % lower bound near 0.82); stronger baselines (LLM given top-k and asked to flag conflicts) and ablations (no weighting, no grouping, no masked gate). |
| 2 | **Judge cascade** | Rules cannot read paraphrase or scope well. | rules, then a local NLI cross-encoder (transformers.js is already a dependency; Xenova ports of `nli-deberta-v3` exist), then the chat model only for the uncertain band. Add `rejudge --where judged_by='offline-rules'`. |
| 3 | **Conflict types and temporal validity** | Many conflicts are just a newer version of the same source's document. | `documents.supersedes_document_id`, `claims.valid_from/valid_to`; auto-supersede within a source with an audit row; show *update* vs *disagreement* in the UI; populate `claims.subject`. |
| 4 | **Learn from admins** | Resolutions are labelled preferences and dismissals are labelled false positives. | Fit the scoring weights on them; show how often the system's lean matches the admin's choice. Bayesian source reliability instead of `1 - 0.5·losses/total`; count independent *sources*, not claims, for corroboration. |
| 5 | **Position-level resolution** | Keeping the minority side supersedes only one corroborating claim; the others stay open. | Resolve every claim in the losing position in one step. |
| 6 | **Hybrid retrieval and filtered HNSW** | Vector-only retrieval; `status = 'active'` is applied after the ANN scan, so superseded claims can leave fewer than k results. | Claim-level `tsvector` + reciprocal rank fusion; `SET hnsw.iterative_scan = relaxed_order` (pgvector 0.8+); an `embedding_model` column for safe re-embedding; benchmark on 100k synthetic claims. |
| 7 | **Answer verification** | LLM answers cite `[C12]` unchecked. | Check every citation is in the evidence set and that both sides appear when a conflict exists, else fall back to the template; abstain below a similarity floor. |
| 8 | **Ingest race** | Candidates are searched before the transaction, so two concurrent ingests might miss each other (not reproduced). | `pg_advisory_xact_lock` or a post-commit reconcile. |
| 9 | **Product and database showcase** | | Conflict-cluster graph view (`conflict_cluster` has no UI); provenance spans; ingest dry-run; URL/PDF ingest; answer-drift alerts; row-level security; `LISTEN/NOTIFY`; token revocation; an ingest rate limit; rate limiter in an UNLOGGED table. |
